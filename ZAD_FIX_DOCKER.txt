## **PART 1: THE CORE-FIRST MANDATE (THE BLUEPRINT)**

This is the strategic plan that must be followed to get the "all-purpose" project working.

### **Step 1: Isolate and Prove the Core Function**

Before you touch Docker Compose, or any other part of the system, your only task is to prove that **factory-core can successfully create and get a response from a single domain-agent via NATS**. This will be done with a single, self-contained script.

  * **Requirement**: Create a new Node.js script named `core_test.js`. This script will:
    1.  Start the `factory-core` service programmatically.
    2.  Start a single `domain-agent` (e.g., the `backend-agent`) programmatically.
    3.  Use a hardcoded PRD to trigger the `factory-core` to create a meta-agent.
    4.  The `factory-core` will then send a task to the `domain-agent` via NATS.
    5.  The `domain-agent` will process the task and send a response back to the `factory-core` via NATS.
    6.  The `core_test.js` script will listen for the final output and print it to the terminal.
  * **No Dependencies**: This script should not rely on Docker. It will use Node.js to directly run the services. The only external dependency allowed is a running NATS server.
  * **Clear Output**: The script must print a clear "SUCCESS" or "FAILURE" message to the terminal, along with the final result from the agent.

**DO NOT PROCEED TO STEP 2 UNTIL THIS SCRIPT RUNS SUCCESSFULLY AND IS MANUALLY VERIFIED.**

### **Step 2: Build a Minimal Docker Compose Wrapper**

Once the `core_test.js` script is working, you will create a minimal `docker-compose.core.yml` file that replicates the proven functionality in a containerized environment.

  * **Requirement**: This Docker Compose file will only include the services necessary for the core function:
      * `factory-core`
      * One `domain-agent`
      * `nats`
      * `redis`
  * **Focus**: This step is only about getting the proven core logic to work within Docker. Keep it minimal. No other services should be included.

### **Step 3: Implement a True End-to-End Test with Real Data**

With the core services running in Docker, you will now create an automated end-to-end test that verifies the entire workflow.

  * **Requirement**: Create a new test script that:
    1.  Sends a POST request to the `factory-core` API running in Docker with a real PRD.
    2.  Polls the `factory-core` API for the status of the meta-agent until it completes.
    3.  Verifies that the final output is correct.
  * **Purpose**: This test will be the ultimate gatekeeper. If it passes, the entire critical path of the application is confirmed to be working in a containerized environment.

**DO NOT PROCEED TO STEP 4 UNTIL THIS E2E TEST PASSES RELIABLY.**

### **Step 4: Build Out the Supporting Services and Full UI**

Only after the core function is proven and validated by a real E2E test can you begin to add the rest of the services to your Docker Compose file and build out the full application.
